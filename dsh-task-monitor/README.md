# dsh-task-monitor · DSH 右侧「任务监控」独立面板插件

给 DeepSeek Harness（DSH）官方桌面版加的本地插件：在**窗口右侧**显示一个**独立的任务监控面板**（不是侧边栏标签页），按会话显示五块只读信息：

| 区块 | 内容 | 交互 |
|---|---|---|
| 环境信息 | 变更统计（+新增 -删除，绿红）、工作区路径、git 分支、未推送提交数 | 「提交或推送」按钮弹对话框 |
| 后台进程 | 本会话后台任务（官方 ctx.jobs 实时名单） | 运行中转圈 / 完成打勾 / 失败打叉 |
| 技能与 MCP | 本会话调用过的技能清单、MCP 服务清单（含调用次数） | 只读 |
| 产出 | 本会话新建/写入/修改过的文件 | 点击在右侧打开文件预览 |
| 网页查阅 | 本会话抓取过的 URL、搜索过的关键词 | 点 URL 用系统默认浏览器打开 |

**显隐规则**：会话已建立（新会话发出第一条消息后）且右侧边栏收起时显示；右侧边栏一展开就自动隐藏。面板显示时正文会像打开侧边栏一样整体左移，不会被遮住。

**快速开关**：会话头部右上角有一个任务清单图标按钮（悬停显示「隐藏/显示任务监控面板」）；「设置 → 通用 → 任务监控面板」里也有同一个总开关（默认开）。

**提交对话框**：分支选择（可切换）/ 提交说明输入（留空自动生成）/ 包含未暂存变更勾选 + 「+X -Y」统计 / 同步状态行（本地与远端差几个提交；远端仓库已删除时如实红字提示）/ 推送 · 提交并推送 · 提交 三个动作；执行结果留在对话框里不自动关闭。

**GitHub 一步到位**：
- 仓库还没关联远端时，对话框里直接「发布到 GitHub」——填个仓库名，再选**私有（只有自己可见）**还是**公开（开源）**，插件自动建仓库 + 配好远端 + 把代码推上去，成功后给出仓库地址（不用去网页点、不用装 gh 命令行）
- **远端仓库被删了也能原地重建**：插件会用 `git ls-remote` 真问一次远端还在不在。仓库已在 GitHub 上被删除时，对话框不再谎报「本地与远端已同步」，而是红字说明远端已不存在，并给出「重新发布」区——仓库名默认填旧仓库名（想换名字直接改），重新发布会新建仓库并把本地远端改指向新地址再推送
- 仓库还没有任何远端时，「推送」「提交并推送」按钮先禁用（悬停有说明），引导先发布；避免点了才报错
- 登录用「两步走」（对话框里直接引导）：① 点「打开令牌页面」——GitHub 会自动勾好建仓库/推送所需权限，滚到底点绿色按钮生成；② 复制那串令牌粘回对话框，点「验证并登录」。登录一次长期有效
- 电脑上本来就登录过 GitHub 的，先点「我电脑上登录过 GitHub，自动导入」——插件会从系统凭据里找回登录信息并存好
- 需要机器上装了 Git（Git for Windows 或 GitHub Desktop 自带都行）；没装时推送会提示去官网安装。国内网络访问 GitHub 时好时坏，失败可直接重试
- **梯子开着就能用**：插件会自动识别本机常见代理端口（Clash 7897 / V2Ray 10809 等）并让推送和登录请求都走代理，不需要你手动配 git 代理；没开梯子时走直连

## 结构（双面插件）

- `index.js` — 宿主半边：`/taskmonitor/data`（五块数据）与 `/taskmonitor/open-url`（系统浏览器）等本机路由；git 只读。
- `client.js` — 界面半边：往官方根级槽位 `shell.overlay` 注册浮层 + 面板渲染 + 显隐/让位规则；数据经 `fetch` 拉本机路由。
- `cordis.patch.yml` — bundle patch（把插件行插入 profile roster）。
- 所有工具名归类以 DSH 0.2.0-rc.2 实测为准：`skill` / `mcp__*` / `write` / `edit` / `str_replace_editor` / `web_fetch` / `web_search`。

## 安装（不改 DSH 官方安装目录）

**一键安装（推荐）**：用 PowerShell 进入仓库根目录（含 `install.ps1` 的那一层，即本文件的上一级），运行：

```powershell
.\install.ps1
```

脚本自动完成下面手动两步（建联接 + 登记 package.json），可重复运行、已装的部分自动跳过；在 Windows PowerShell 5.1 下若中文提示乱码只是显示问题，功能不受影响（推荐 PowerShell 7）。装完**重启 DSH 桌面版**生效。

**手动安装**（与脚本等价）：
1. 建目录联接：
   ```powershell
   New-Item -ItemType Junction -Path "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\@local\dsh-task-monitor" -Target "<本目录绝对路径>\dsh-task-monitor"
   ```
2. 编辑 `~/.dsh/profiles/desktop/package.json`：
   - `dependencies` 增加 `"@local/dsh-task-monitor": "link:<本目录绝对路径>/dsh-task-monitor"`（斜杠用正斜杠）
   - `dsh.profile.bundles` 追加 `"@local/dsh-task-monitor"`
3. 重启 DSH 桌面版后生效。

> **改代码后怎么生效**：宿主半边（`index.js`）改动必须**重启 DSH**（DSH 的 loader 不做模块缓存失效，重挂载仍拿到旧代码；插件管理器自己也会提示「需要重启」）；界面半边（`client.js`）改动刷新页面（Ctrl+Shift+R）即可。开发期想少重启，可先把改动集中到 `client.js`，宿主改动攒一批再重启。

## 卸载

把上面两步改回（删依赖、删 bundles 条目、删联接），重启 DSH。插件源码可保留。

## 安全边界

- `/taskmonitor/*` 只接受本机环回请求（socket + Host 头 + 同站校验）。
- git 只能读「已注册工作区」目录，且只有只读命令。
- `open-url` 只放行 http/https。
- 除「把 URL 交给系统浏览器」外无任何写副作用；不缓存、不落盘、不主动外联。
